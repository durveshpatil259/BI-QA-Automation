      How a run works

      Nine stages, all automatic once you press Analyze.

      1. Extract metadata — pages, visuals, measures, tables and relationships are read from the file. No AI.
      2. Read the datasource schema — tables and columns from SQL Server, or the sheets of a workbook.
      3. Evaluate DAX — measures are computed from the data inside the file, giving the value the dashboard would show.
      4. Build the analysis context — deterministic checks over the model itself.
      5. Analyse with AI — a short narrative summary. One call.
      6. Generate SQL — measures whose DAX Python can express are compiled directly; only the remainder is sent to the model.
      7. Execute and compare — queries run against the source and Python compares the numbers.
      8. Select test cases — candidates are generated, deduplicated by what they prove, and trimmed by priority.
      9. Build the report — HTML, PDF and Excel.

      What a result means

      Pass The source value matched the dashboard within tolerance
      Fail The values differ, or the query could not run
      Warning Executed, but something needs a look
      Not executed A manual test case — nothing automated proves it

      Pass and fail are decided in Python by comparing numbers. The model is never asked whether two values agree.

      Current limits

      • Power BI is fully supported. Tableau files are detected and declined — no parser is implemented.
      • Chart validation confirms that the categories exist in the source; it does not compare plotted values, which a file cannot supply without a screenshot.
      • A few advanced DAX functions cannot be compiled and fall back to generated SQL, which is less reliable.
      • Suites showing 0% coverage contain manual test cases, not failures.
